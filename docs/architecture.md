# 工程职责与边界

## 数据如何变成阅读材料

原始PDF → 智能体通读与解释 → JSON记录 → 引文定位与排版 → 机械检查 → 人工/独立内容审查。

| 环节 | 负责什么 | 不负责什么 |
|---|---|---|
| SKILL.md与智能体 | 理解语境、选重点、写解释、保留条件和来源 | 不保证自动理解正确 |
| annotations.json | 固定版本、SHA256、准确引文、页序、解释、类型与关联 | 不是原论文本身，也不是模型输出正确的证明 |
| annotate.py | 校验版本/引文、映射原生字符框、计算旁注位置、绘制、报告 | 不调用模型，不自动总结 |
| academic_guide.py | 分析版式、整理给定内容、规划和渲染导览、建立GoTo | 版式分析是启发式，不是自动语义理解 |
| verify.py / prepend_guide.verify_inserted | 重新打开成品，检查对应路径的文字、几何、对象或像素 | 不验证学术解释正确 |
| mobile.py | 将最终PDF渲染为原页HTML，复用定位及版本哈希 | 不是全文可检索HTML或自适应重排阅读器 |

真实记录例如保留完整的`sequence transduction`原句和本文义，具体见[样例JSON](../examples/attention-is-all-you-need/annotations.json)。原句经兼容字符/空白规范化匹配后映射回原生字符框；重复引文需明确出现次数，不能默认取第一次。

## 两条 PDF 路径

| | 只插阅读导览 | 添加正文旁注/高亮 |
|---|---|---|
| 入口 | scripts/prepend_guide.py | scripts/annotate.py |
| 研究页处理 | 在原对象树前插1页，不重绘研究页 | 原PDF视觉内容置入新页面，再添加标记和文字；必要时扩边，正文不缩放 |
| 验证 | 原页逐页72dpi像素/文字一致；链接、书签、元数据；样本还检查批注、表单值、附件及页标签 | 引文定位、原正文文字、批注几何及可见文字；不能宣称全部原结构保留 |
| 原有批注/表单 | 已有合成样本检查 | 发现时拒绝，防止静默丢失 |
| 原书签 | 原层级与目的地保留；已解析的命名书签转等价GoTo | 重新生成页入口，不保证保留原书签/链接 |
| 输入 | 不覆盖 | 不覆盖 |

只插导览路径拒绝加密、修复后异常、旋转/非平凡裁剪和签名文档。原标签树存在性保留，但新增导览未做PDF/UA标记，未认证完整辅助技术语义；XFA、作品集、富媒体不在已认证范围。正文标注同样不支持加密、旋转/异常裁剪；不能把只插导览路径的拒绝条件和保留结论当作它的完整保证。

当前 Attention 样例原页3–5不扩边，其他页面或文档可能扩边，字体不会为塞内容而小于9pt。结构与视觉保留结论须按上表对应路径区分，不能把“原始文件未覆盖”写成“标注成品每个像素均不变”。

## 失败时怎么处理

版本哈希不同、引文找不到或有歧义、旋转/异常裁剪、缺字、旁注与正文冲突或放不下会停止并给出错误。删减重复解释、缩短文字、再调整位置，最后才考虑扩边。脚本未认证的复杂PDF结构需单独检查，不静默宣传兼容。
