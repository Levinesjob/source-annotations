# 发布步骤

本阶段以已有能力达到可发布、可使用的水平为目标，按[项目计划](../PROJECT.md)推进。当前状态以 [review/STATUS.md](../review/STATUS.md) 为准；下列步骤是待执行检查，不代表发布已经完成。

1. 核查 README：用途、真实效果和入口靠前；三种使用方式、依赖与边界清楚。截图、数字和链接对应当前案例。
2. 在干净目录按 [使用说明](usage.md) 安装、获取固定原文并生成样例，运行测试和 `scripts/verify.py`，检查关键跳转与可见页面。记录环境、命令及结果；机械验证不能替代内容审查。
3. 复核公开展示中的解释、结果和证据对应关系。已知关键误译、错误跳转或无法生成等问题先修复。更新 TODO、状态和版本记录，检查反馈模板；未完成的独立审查、真实手机和效率实验如实披露，限制对应宣传。
4. 确认发布账号为用户期望账号。当前连接显示Levinesjob；仓库默认source-annotations。
5. 仅上传 `scripts/`、`references/`、`agents/`、`assets/`、`examples/`、`tests/`、`docs/`、`.github/`、`output/` 中审查过的文件，以及根目录文档。`.venv/`、`local/`、原始聊天和账号信息不能上传。公开独立报告须移除本机绝对路径和无关上下文。
6. 更新已有公开仓库main；本轮不重写历史Release标签。逐项核对第三方许可；当前Attention全文仅本地生成，不能因旧例曾允许分发而沿用。
7. 从公开版本重新下载，执行README最短路径，核对可见样例与版本对应。
8. 基于发布内容先写一篇操作演示，再参与相关讨论；链接使用实际发布地址。优先收集安装失败、解释错误、跳转与阅读障碍，依据反馈修复，视频按实际需要制作。

历史 `v0.1.0-preview.1` 属于旧案例，不复用该标签，不作为当前 Attention 版本入口。若创建新 Release，使用未占用版本号并列出实际资产和验证范围。新网站、额外框架和量化提速实验不作为预览版的默认前提；已知错误和使用路径失败不能靠“预览版”标签略过。
